# Atropos v1.2.0 — Design Brief (internal)

Target: v1.1.0 (49 tests green) → v1.2.0. Every MUST from the brief + hard rules.

## Review findings folded in (2026-08-15 adversarial panel)

Decisions locked by the review:

1. **config.DEFAULTS stays untouched** in core/config.py (legacy-compat layer). settings.py is layered ON TOP: reads go through `settings.get()`; writes through `settings.set()` (validated) — legacy writers (guest.toggle, router.set_active, skills.set_routing, setup_wizard, api_config_set) keep using config.set_path/config.save, which is accepted: the file is shared, validation happens at the settings/API boundary, and the schema defaults exactly equal today's hardcoded values so behavior is preserved.
2. **Unknown-key semantics**: `settings.get(unknown)` → None (test_core.py:169-170 requires it); `settings.set(unknown)` → ValueError. Type coercion in set: `"8787"` → 8787; `dashboard.port abc` rejected.
3. **`settings.get()` must return the NESTED legacy shape** for `api_status.config` / TUI dump (dictionary merging per config.DEFAULTS nesting — NOT a flat map for the file; the schema's flat keys map onto the nesting).
4. **Secrets**: `alerts.token` + `dashboard.password` flagged `secret: True`. Masking (`***`) in: `/api/settings` GET, `/api/config`, `/api/status` config blob, `history_log` for any settings/config write of a secret key, and `settings export` (unless `--secrets` flag). Also scrub pre-existing history lines containing `alerts.token=` / `dashboard.password=` at dashboard boot.
5. **Legacy `api_config_set` stays** (back-compat) but gains schema validation: unknown key → error; type coercion via settings; secret masking in history_log.
6. **Windows**: extensions install/remove use shutil.copytree/rmtree — never os.symlink for install (existing skills.sync_to_hermes keeps its symlink behavior but wraps errors: falls back to copy on OSError). `termios` remains POSIX-only in tui.py but guarded by platform check with a graceful message (baseline already imports it lazily inside _read_key; wrap import in try/except and print "TUI requires a POSIX terminal").
7. **SSE hub** (`core/sse.py`): subscribe/unsubscribe on write-failure; per-client bounded queue (drop-oldest, cap 200 frames); max 32 clients; heartbeat keepsalive; eviction on broadcast failure; `?token=` accepted (documented) — and `ATROPOS_LIVE` gating via `dashboard.live` (default True).
8. **Failover**: `failover.retries` counts consecutive failures (persisted); on switch, `alerts.send_alert` (gated by `alerts.events.router`); when all routers in order exhausted → terminal state `all_down=True`, no wrap-around re-ping loop; `failover.order` validated to only contain nain/omni/local and to include the active router; hysteresis: switch only after `retries` consecutive failures, and back-off manual `route set` remains authoritative (failover marks state, it does not fight manual choice for `failover.hold_minutes`).
9. **Console**: `/api/run` serialized through a module-level `threading.Lock` (one side-effecting command at a time); identifier regex `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$` enforced for ALL names (skills/plugins/marketplace); max concurrent runs = 1 (queue); no stdout capture — each command returns structured output_lines built by the handler itself.
10. **Marketplace**: `ATROPOS_MARKET_URL` override honored ONLY when `server` env var `ATROPOS_TESTING=1` is set... actually: accept override only for hosts already in the allowlist (host must be one of `raw.githubusercontent.com` | `api.github.com`) — SSRF-proof by construction; per-item size cap 5MB; identifier regex on all names.
11. **update bump**: `apply_update()` operates on the HERMES-AGENT repo; the CHANGELOG + VERSION live in the ATROPOS repo. So: after `api_update(check=False)` succeeds, dashboard.py bumps the ATROPOS-side `docs/CHANGELOG.md` (prepend `## [x.y.z]` from the new hermes VERSION if a new entry is warranted... simpler: update.changelog_bump flag default True; bump_changelog() prepends an `## [version] — auto (release)` entry recording the hermes-agent head) and never touches VERSION (VERSION stays the atropos release; bumped manually/at release). Document this split.
12. **refresh_ms**: frontend polling intervals read from `/api/settings` boot payload → `dashboard.refresh_ms` (default 10000) drives the 10s loop; the 30s version-loop stays fixed; SSE is the live channel, polling remains as fallback (dual-path is fine but intervals come from settings).
13. **docstrings**: new modules 100% docstringed; existing core modules — add missing docstrings to public functions touched by v1.2.0 (config, router, watch, alerts, backup, dashboard api_* that we touch). Full-baseline docstring sweep is beyond scope — the hard rule is enforced on all NEW code and on touched functions.
14. **jailbreak.auto_apply** (default False) wired into `doctor --fix` completion (a `settings.get('jailbreak.auto_apply')` hook in the doctor API path) — inert otherwise.
15. **backup.retention** (default 5) wired into backup.create/prune; **watch.state_db_mb** (100) + **watch.log_max_mb** (50) + **watch.threshold_disk** (80) + **alerts.min_interval** (600) + **alerts.events.*** wired into their respective sites.
16. **skills.routing** in schema as `map` type; default = DEFAULT_ROUTING deep copy.
17. **dashboard.live** (default True) added; **effort_default** mapped to the per-harness fallback dicts in dashboard.py + atropos CLI.
18. **hermes.home / hermes.log_channel / claude.model / claude.alias / version** stay in config.DEFAULTS (computed/legacy); schema marks them readonly/computed and never validates user writes to them.
19. **run_tests.py** pattern → `test_*.py`.
20. **Session export** = JSON lines of sessions (small, safe); search = LIKE across the message table's content column (bounded 5s timeout, limit 50).

API:
- `get(key)` / `get_all()` / `set(key, value)` — **typed coercion + validation**; rejects wrong types (the `dashboard.port abc` test), converts `"8787"→8787`, rejects unknown keys with a clear `ValueError`.
- `keys()`, `groups()`, `schema()`, `export_yaml()` (dump to YAML via config.dump_yaml), `import_yaml(text)`.
- `migrate()` — folds legacy `version` key, maps `alerts.thresholds.disk → alerts.threshold_disk`, ensures every schema key exists in the file (writer keeps file readable).
- Persistence: still `~/.atropos/config.yaml` via config.load/save (back-compat: dashboard/api_config uses same file).

**Wiring rule**: modules import `from . import settings` and call `settings.get("watch.interval")` — never `config.load()` raw. Modules: watch, alerts, router, dashboard, backup, watch, skills, jailbreak, guest (config.set_path stays for file write; reads go through settings).

## 2. Universal extension layer — `core/extensions.py` (NEW)

One abstraction over three stores:

| Store | Root | Item shape |
|---|---|---|
| Hermes skills | `${HERMES_HOME}/skills/<name>/SKILL.md` | dir + SKILL.md |
| Claude skills | `~/.claude/skills/<name>/SKILL.md` | dir + SKILL.md |
| Hermes plugins | `${HERMES_HOME}/plugins/<name>/plugin.yaml` (+ code) | dir w/ plugin.yaml (or .py) |

- `list_extensions(kind='all'|'skill'|'plugin')` → unified entries `{name, kind, source('hermes'|'claude'), path, enabled, description, head}`. **enabled**: skills → SKILL.md exists; plugins → plugin.yaml exists and yaml `enabled: true` (default true).
- `enable/disable(name, kind, source)` — for skills: toggle presence marker file or rename? Skills enabled = SKILL.md present; disable = move SKILL.md to SKILL.md.disabled (reversible, no destructive delete). Plugins: edit `enabled:` line in plugin.yaml (respecting comment preservation).
- `install_skill(source_path_or_name? ...)` — copy dir into target root; `remove` — move to trash dir `~/.atropos/trash/<name>-<ts>` instead of rm (safety).
- Back-compat: `atropos skills` CLI gains `--enable/--disable/--remove`; `api_skills()`/`api_plugins()` in dashboard.py replaced by `api_extensions` (and kept as thin wrappers).

## 3. Marketplace — `core/marketplace.py` (NEW)

Hardcoded allowlist of trusted sources (no arbitrary URLs). Each entry: `{id, name, author, kind: skill|plugin, target: hermes|claude, url, description}`.

Sources (prefer GitHub raw, documented in README):
- `anthropics/skills` (official Anthropic skill collection) — raw.githubusercontent.com/anthropics/skills/main/<skill>/SKILL.md
- `obra/superpowers` (superpowers skills) — raw.githubusercontent.com/obra/superpowers/main/skills/<name>/SKILL.md
- `hermes-skills` community registry (curated, id: hermes-community) — TBD: a well-known org repo raw file
- `arophin/Atropos` own `marketplace/catalog.json` — self-hosted catalog (extension of the allowlist; still allowlisted)

Install = fetch SKILL.md (+ references dir listing) via urllib → write into target root → verify → report. `scan_state()` merges install status per item. Failure of a source → `{ok: false, error}` per-item, never whole-catalog failure.

Testing: `MALLET_MARKETPLACE_OFFLINE=1` or overridable base URL env for tests (`ATROPOS_MARKET_URL`), default points at `raw.githubusercontent.com`; tests monkeypatch fetch.

## 4. Console — `core/console.py` (NEW)

Whitelist dispatcher. Command table:

```
doctor                        → doctor.doctor()
doctor --fix                  → doctor.doctor(fix=True)
self-heal                     → dashboard.api_self_heal()
backup create                 → backup.create()
backup list                   → backup.list_backups()
update check                  → update.update_check(repo)
route test [name]             → router.ping(name)
route set <name>              → router.set_active + apply_all  (nain/omni/local only)
skills list / skills install <name> / skills remove <name>
plugin enable <name> / plugin disable <name>
status / version / effort get
help
```

- Parser: shlex.split; **token allowlist** — first token must be an exact registered command; each command defines its own allowed arg patterns (regex) and a validator fn. `rm -rf /` → "unknown command" rejection. No shell, no subprocess of user input, no `os.system`.
- `run_command(line)` returns `{ok, output_lines[], command}`; `validate(line)` for the API layer.
- History: `~/.atropos/console_history.jsonl`.
- API: `POST /api/run {command}` → runs (thread) → `{"ok", "command", "output": [lines]}`; SSE hub also broadcasts `event: console` with the output for the Console panel (running per-request, poll fallback).

## 5. Router failover — `core/failover.py` (NEW)

- `check_now()` — ping active router; on failure ≥ `failover.retries` consecutive → switch to next in `failover.order` via router.set_active + apply_all → persist state → alert via alerts.send_alert("Router failover: nain → omni") → history_log.
- State: `~/.atropos/failover_state.json` `{active, failures, last_check, switches: [{ts, from, to}]}`.
- Circuit: reset failures on success. `status()` for API/CLI.
- `watch` hook: run failover check inside watch's `run_watch()` (gated by `settings.get('failover.enabled')`).
- tests/test_failover.py: monkeypatch `router.ping`/`router.set_active` to simulate failures and verify order + persistence + alert called.

## 6. SSE broadcast hub — `core/sse.py` (NEW)

- `Hub`: subscribe/unsubscribe per-client; `broadcast(channel, data)` fans out.
- `/api/events` (auth via `?token=` since EventSource can't set headers) — heartbeat `: ping` every 15s; channels: `status` (every N s per client), `logs`, `console`, `notify`.
- Existing `/api/logs/stream` stays (back-compat).
- Frontend: single `EventSource('/api/events?token=...')` gated by `dashboard.live: true`; panels can subscribe client-side to channel payloads.

## 7. Dashboard panels + theming + i18n

- **Themes**: `data-theme="dark|light|auto"` on `<html>` + accent var swap. CSS: separate `:root[data-theme=light]` overrides; accent via `--accent` / `--accent-l` applied as CSS vars (all existing usages remain; accent changes re-map `--indigo` etc. via JS applying CSS vars).
- **i18n**: `window.I18N = {en: {...}, fa: {...}}` — all 22 panel titles, nav, buttons, toasts, doctor check names, effort tier names, jailbreak names. `t(key)`; `?lang=fa` + `?lang=en` honored at boot, persisted `localStorage('atropos_lang')`, `🌐` button in topbar. RTL: `document.documentElement.dir = 'rtl'` + CSS `[dir=rtl]` flips (sidebar right, text-align). All Farsi strings proper UTF-8.
- **New panels**: `market` (marketplace listing + install buttons), `console` (REPL input + output streaming), `settings` (22nd — settings table grouped by section, edit inline, save → POST /api/settings/set).
- Nav: 22 items → sidebar gets scroll; `⌘K` palette gains new panels + actions (Settings, Market, Console + "run doctor" etc).
- PWA: `dashboard/sw.js` real service worker (cache index.html + sw fallback offline), `manifest.webmanifest` inline via data URL or separate file? Brief allows `dashboard/sw.js` as second file; manifest must then also be registered — add `<link rel="manifest">` to a generated blob? Simplest allowed: sw.js registers and serves index.html offline; manifest inline JSON in HTML via `application/manifest+json` data URI (works in Chromium). Plus PWA meta upgrades.
- Session search/export: `GET /api/sessions/search?q=` (LIKE on content/message table) + `GET /api/sessions/export` (JSON download of sessions; small, safe).

## 8. Watch / update upgrades

- watch: interval + threshold_disk + auto_backup from settings; on detected drift + auto_backup → create backup automatically (`watch.auto_backup`), log.
- update: after apply_update success, auto-bump `docs/CHANGELOG.md` with `## [<version>] — date (auto)` entry? No: changelog auto-bump = insert the version header entry if missing + bump VERSION file to new version by reading latest `## [x.y.z]` — implement `update.bump_changelog(new_version)` that prepends a templated entry, and `update.apply_update` calls it with the new version parsed from upstream VERSION.

## Hard-rule checks baked in

- stdlib only: urllib/urllib.request, sqlite3, http.server, unittest, shutil, json, re — no imports of requests/bs4/flask.
- No secrets in code: token only from env/file; settings secrets masked in export.
- Farsi correct UTF-8; comments English.
- Console dispatcher whitelist-only — enforced + tested.
- Routers nain/omni/local only — settings choices + failover order validate.
- Docstrings on every public fn; no TODO/FIXME; no dead imports.
- Defaults preserve old behavior; new behavior behind toggles (e.g. failover.enabled default True, auto_backup default True but watch.interval default stays 1800).
